WEBCOCKPIT · PHONE REVIEW · 2026-11-01 · BRAINSTORM, NOTHING DECIDED

A phone-first WebCockpit

Three directions for the same feature set, each at two ambition levels: L1 Companion (read, chat, status, map, type) and L2 Light play (plus direction pad, quick buttons and history chips, so you can walk and act without the keyboard). Desktop does not change: everything here sits behind the phone flag.

What hurts today

  • Every target is about 15 px tall: menu rows, tabs, the ☰ (16×14 px).
  • Menus are keyboard pages: footers list keys, cyclers need tiny << >> arrows, grids are 67–76 columns wide and swipe sideways.
  • Everything must be typed; the keyboard takes half the screen; no history, macros dead.
  • MUME is told 80 columns, the phone rewraps to 42: tables break.
  • CHAR, GRP and TIME are each 80 % empty; one tab at a time.
  • The fullscreen corner button covers content on every screen.

Principles

  • Desktop untouched. Phone code behind the phone flag only; desktop e2e unchanged.
  • Read at the top, act at the bottom (thumb reach).
  • 44 px minimum target, no keyboard hints on touch.
  • Game text first: chrome folds away when the keyboard is up.
  • Configure on the computer, adjust on the phone: a small settings subset.
  • No keyboard needed for common actions (L2).

The three directions

  • A Terminal — pure TUI made big: box cells, bottom TUI tab bar, Termux-style key row. Profile: select only.
  • B Hybrid — TUI game and panes; chrome as surface panels, bottom nav, bottom sheets, chip bars. Profile: simple list editor.
  • C Touch-native — app bar, drawer, chat view, cards, floating pad, sans type around mono text. Profile: list + code.
